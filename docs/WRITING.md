# 剧本写作需求（给每一个写剧情的会话）

> 这是用户对剧情内容的全部要求的汇总。**新开会话写剧本之前先读完这一篇**，再按需查阅后面列出的细节文档。
> 每条要求后面的 D-xxx 是开发日志里的决策编号，想知道"为什么"就去 [DEVLOG.md](DEVLOG.md) 查。

## 1. 总原则

| 要求 | 说明 |
|---|---|
| **语言** | 剧情、对话、文档、提交信息、和用户的交流，一律用中文。 |
| **金庸同人，文字全部原创**（D-025，STORY.md §6） | 人物、门派、武功名称沿用原著；叙述、对白、招式描述**全部自己写**。不摘抄原著段落、诗词、回目（章节名也要原创）、标志性台词。非商业。 |
| **玩家是原创角色**（STORY.md §2） | 玩家不扮演郭靖、张无忌等主角，而是亲历其事的江湖人：与原著人物同行、相助、对立。 |
| **原著大走向不改** | 玩家可以影响细节、做选择（如亲手了结段天德或交给七怪），但不改变原著的主要结局。选择用标记记下，后面的剧情可以读它。 |
| **一个江湖，不讲时间线**（STORY.md §3 方案 A） | 所有主线共用一张地图，同时存在。 |
| **一部小说一条主线**，多线并行 | 每条主线一个目录 `content/<主线>/`，只能写自己命名空间的标记（STORY.md §4.2）。 |
| **射雕 → 神雕 → 倚天是三部曲**（D-141，用户 2026-10-21 定） | 前一部完结之前，后一部不能触发：`storyline` 块写 `requires: 前一部的主线id`，引擎按前一部的 `done:` 判断。一部的结局导向下一部的开始；可以在前一部埋伏笔，到后一部再揭开（射雕埋下的见 SHEDIAO.md §4）。 |
| **重剧情、鼓励联机** | 剧情要有分量；能双人做的地方尽量给组队的玩家额外的路或奖励。 |

## 2. 章节怎么写

- 每章一个文件 `content/<主线>/chNN.md`，在 `content/index.json` 里按剧情顺序登记。**文件顺序就是剧情顺序**：战力检查按这个顺序累计（POWER.md §3）。
- 每章大约：3~6 个新地点、2~3 场战斗、一两个可选的分支或支线、章末奖励。
- 必备的块：`chapter`（`done:` 完成标记、`start:` 重来的地点、`retry:` 重来的提示）、每一步的 `goal`（当前目标）。
- **主线开始前的提示**（D-097）：`storyline` 的 `hint` 只写第一步去哪找线索，不要剧透后面的事。开始前要经过几步的（如竹哨线：找乞丐 → 吹竹哨 → 住店），用几条 `pre: true` 的 `goal` 按条件分阶段给。
- **目标要把"怎么做"藏起来**（D-074）：`goal` 的 `name:` 只写做什么（如"查西湖命案"），这是玩家直接看到的；正文写具体怎么做（去哪、找谁、门槛是什么），玩家点"提示"按钮或输入 `提示` 才显示。正文不要再重复标题。
- 主线（`storyline`）写 `xiuwei: 起-止`，是**建议修为**（D-075）。修为 = 刚、巧、守三势最狠一招的攻击值之和 + 气血上限 / 5，敌人用同一个公式（D-107）。不用自己算：写了新章节后跑 `node tools/validate.mjs`，它会提示该改成多少。
- **主线的三个天赋点**（D-108）：`storyline` 块的 `milestones:` 写两个条件，分别是全线**三成左右**（20%~40% 的章节）和**七成左右**（50%~80%）那一章重要战斗（一般是章末的头目战）的胜利标记；写完终章时加 `done: 终章的完成标记`。各给 1 点。按规划的总章数算位置，写到那一章时再补上。
- 章节名原创，格式"第N章　四个字"。
- 剧情对玩家的称呼用 `{姓名}`，按性别区分用 `{男:兄台|女:姑娘}`。
- 写完一章，**删掉上一章结尾的占位文字**，并在 [TODO-CONTENT.md](TODO-CONTENT.md) 里划掉。还没写的后续一律在 TODO-CONTENT 里登记。
- 已埋下的伏笔优先回收（TODO-CONTENT"埋下但还没接续的伏笔"）。
- 往返：剧情专属地区必须能随时回到主地图（练功、买东西），章节结束后也能再去。
- **剧情中间换房间**：`goto:` 要放在一个**自己没有选项的过场对话**里（范例 `shediao.hb.sail`、`tianlong.c1.fall`）。写在有选项的对话的 `do:` 里，新房间的触发会把选项顶掉；写成选项的效果，又会被 `endDialog` 关掉（D-211）。
- **章节的 `start:`（打输重来的地点）要选玩家会自己走回去的地方**：回到检查点时引擎不跑房间触发，人被直接放回去。若 start 正是靠触发推进的房间，玩家会站在原地什么也不发生（D-213）。放在城里的车马行、客栈最稳妥，顺带方便先去练功。
- **可选支线要留出空当**：把"打完一场 → 下一段剧情"写成一串连着的对话，玩家就没机会拐去支线。该断的地方断开，用房间触发接上（D-210）。
- **往共享房间加出口之前，先看这个方向有没有人占**（D-230）：`node tools/exitcheck.mjs`。实在没有空方向，就把剧情地区挂在自己主线的房间上，多走一步也比把别人的路顶掉强。另外跑 `node tools/mapcheck.mjs`（D-131）：挂上去的地方在地图上被房间挡住、只好挪开的会列出来，有空方向就换一个，免得地图方位和正文说的对不上。
- **分支不是只能靠门槛**：选项条件还可以是物品（`?has:`）、门派（`?sect:`）、性别、修为。用前面章节发的物品开分支，考的是"你这一路留下了什么"，比再写一道功力门槛有味道（D-228，天龙第二十二章的渡口）。

## 3. 战斗

| 要求 | 说明 |
|---|---|
| **除第一章外，每章都要有战斗**（D-042） | |
| **剧情战默认必须打赢**（D-042） | 打输回到章节检查点（标记回滚，人回到 `start`），经验潜能物品保留，一次性奖励不重复发。 |
| **难度标准：猜对 80% 能赢**（D-051） | 必胜战按玩家当前功力自动调整敌人气血，猜对 80% 的招时胜率约 65%。写完用 `node tools/balance.mjs <战斗id>` 核对，三种角色在"猜对 80%"一栏应在 60%~80%。 |
| **允许打输的剧情战** | 战斗块写 `lose:`，输了剧情照常继续，打赢另有奖励（如第二章的段天德）。 |
| **NPC 队友**（D-072） | 剧情里有原著人物并肩作战时（如和郭靖一起对敌），战斗块写 `allies:`。NPC 由电脑出招，每回合开始公开他要出的招；玩家可以用辅助招式给他疗伤、加持，用守招护住他，满足条件可以和他使出双人技。NPC 倒下不算输。见 §5。 |
| 敌人写法 | `enemy` 块；兵器 `weapon`、称呼 `weaponName`；强敌可以有 `cunning`（虚招）、`obscure`（藏招）。敌人的战斗力用 `node tools/power.mjs` 看。 |
| 群攻（D-081） | 招式效果 `群攻`：打到所有对手，多人时每人六成伤害。适合"一人对一群"的剧情（如乔峰聚贤庄）。 |
| **强敌要少**（D-222） | 自适应同时调敌人气血（0.25 ~ 3 倍）和伤害，按玩家刚巧守三势最狠的招和气血直接算（D-106），所以战斗力 150 以上的剧情战，同场敌人压到两个（头目＋一个小兵）。要表现"几百人围攻"，靠文字和分几场打，别把四五个高手塞进同一个战斗块。 |
| 平衡模拟的四种角色 | `balance.mjs` 有开局／入门／二袋／后期四档。前三档量前期剧情，十几章往后的剧情战看"后期"那一行（D-222）。 |
| **报表上 50% 出头又调不动，先怀疑量法**（D-227） | 自适应只用 40 次模拟拟合气血，会过拟合；`balance.mjs` 已改用 200 次。固定种子下同一场战斗结果完全一样——所以"多跑几次看看"没有意义，调敌人等级也没有意义。 |

## 4. 战力门槛（D-060、D-066）

后面的章节可以要求玩家功力达到一定层次才能推进（"推开巨石要气血 600"之类）。规则：

- **门槛三选一**：同一个门槛给三条路，各对应一种成长方向，玩家满足任意一条即可：
  1. 一门某势外功到某级（`?stance:巧:30`，翻墙、轻巧的路）；
  2. 气血上限或内功等级（`?maxhp:380`、`?inner:25`，硬闯、硬扛的路）；
  3. **两人组队**（`?party:2`，给联机的路）。
- 条件都不满足时，给一个"现在还不行"的选项，**写明需要什么**，并让玩家能离开去练功（门槛对话不要锁定，触发条件不要关掉）。
- 当前目标（goal）里也写明门槛。
- 数值参考：射雕第四章（金营）巧 20 / 气血 380；第五章（王府）巧 30 / 内功 25；竹哨第四章 刚或巧 45。越往后越高。

## 5. 鼓励联机的设计

- **组队选项**：门槛的第三条路（§4）；可选的双人机关（如竹哨线的千斤闸 `?party:2`，单人看得到但打不开，提示"和朋友组队后再来"）。
- **辅助武功**（D-064）：每个门派一门，给队友疗伤、回气、振奋、护体、解穴。
- **双人技（合击）**（D-065，`content/world/combos.md`）：两人同一回合用特定的两门武功出招触发，对手的克制不影响合击（D-080）。每两个门派之间都有，高级低级都有。剧情里的 NPC 队友也算一方（D-072）。
- **合击里用到的武功必须定义在 `content/world/`**（D-083）：主线没加载时，合击页和组队时的对方武功也要认得它。剧情传授的武学一律写在 `content/world/arts.md`，id 用主线前缀（如 `shediao.yuenv`），怎么得到写在主线里。
- **写 NPC 队友时**：
  1. 用 `enemy` 块定义 NPC（武功、等级、兵器、`ai`），id 用 `<主线>.ally.<名字>`。
  2. 战斗块写 `allies: <id>`；战斗描述里交代他为什么并肩作战，并提示玩家"他每回合要出的招会显示出来"。
  3. **给他配合击**：在 combos.md 里加一个"NPC 的武功 + 玩家这时很可能会的武功"的合击（例：韩小莹的越女剑法 + 玩家第三章学的全真剑法 →「剑影双飞」）。这样玩家能体验和原著人物的配合。**不要配武馆的基础武功**（庄稼把式、三才剑、小巧掌等），校验脚本会报错（D-098）；玩家这时还没有合适的剧情武学或门派武学，就不配合击，章节里也别写"可以使出双人技"。
  4. NPC 不要比玩家强太多，否则战斗就成了看戏。必胜战的自动调整会把 NPC 的帮助算进去。

## 6. 剧情传授武学秘籍（D-068，详见 [POWER.md](POWER.md)）

- 过剧情时要把**相关的武功秘籍传授给玩家**（如射雕：杨家枪法、全真剑法、越女剑法、全真心法……）。
- **平衡规则：玩家必须打得过战斗力 X 的敌人，才能得到威力不超过 X 的武学。** 避免早期就拿到最终的强力武学，后面的武学都没用了。
  - 威力和战斗力是同一把尺子（攻击值），`node tools/power.mjs` 计算；`node tools/validate.mjs` 违规会报错。
  - **秘籍先给低上限，随剧情提高**：第一次传授给低上限（`cap` 属性），后面的章节用 `cap:武学:等级` 提高。每次都要符合规则。
  - 授予放在本章战斗之后。
- 门派武学由门派传授（拜师、阶位），剧情不给门派武学。反派武学只给敌人用。
- 射雕后续章节的秘籍规划见 POWER.md §6。

## 7. 防止"中途离开就丢东西"（D-067）

玩家在没有 `lock: true` 的对话里输入别的命令，对话就结束了。所以：

- 战斗结果之后、`once` 触发之后、触发条件已关掉之后的剧情对话，一律 `lock: true`。
- 任务物品在进入对话时就给（`do: give:…`），选项只做确认。
- "已经发生过"的标记和物品放在同一个选项里，不要先设标记、下一步才给物品。
- 校验脚本会检查这几条。

## 8. 文字细节

- 招式描述里用 `$N`（出招者）、`$n`（对手），**不要写死"你"**：玩家自己出招时 `$N` 就是"你"，会变成"你趁你不备"。
- 预兆（`omen`）可以用 `|` 写几种，随机挑。
- 门派、地点、人物的介绍放进百科（`entry`），正文里用 `[[名字|id]]` 链接。

## 9. 写完一章的检查流程

1. `node tools/validate.mjs` 通过（引用、命名空间、锁定、战力规则）。
2. `node tools/power.mjs`：本章授予的武学全部 ✓。
3. `node tools/balance.mjs <战斗id>`：每场必胜战"猜对 80%"在 60%~80%。多个敌人时，最强的写在 `enemies:` 第一个（D-091）：平衡模拟和玩家都默认先对付第一个，弱的排在前面会让胜率和读预兆脱钩。
4. **打输重来以后，那场战斗还能再触发**（D-091）：重来时剧情标记回到章节检查点，人回到 `start`。如果某场战斗是从检查点之前就已关掉的对话里开打的，重来后就再也打不了，主线卡死。检查每一场必胜战：检查点之后，有没有一个触发能重新把它开起来。
5. **`node tools/exitcheck.mjs`：出口有没有被顶掉**（D-230）：房间出口是"原块 ＋ 所有生效的 patch 逐方向合并"，**同一个方向被后来的 patch 指到别处，原来的去处就没了**。各条主线都往车马行、少林这些共享房间上挂剧情地区，八个方向很快不够分；撞了车，玩家走到某一章就再也回不去——validate 查不出来。
6. **`node tools/goalcheck.mjs <主线id>`：当前目标的连贯性**（D-226）：上一章写的收尾目标（"本线暂告一段落""后续尚未编写"之类）要删掉或改条件，否则它会一直挡在玩家眼前——validate 查不出来。脚本沿章节顺序把标记一个个设上，报出"被更早章节的目标挡住"的步骤（"当前目标为空"只是提醒，互斥分支的标记同时为真也会这样）。
7. 写一个脚本把本章从头走到尾（参考以前的测试方法：创建 Game、设好前置标记、依次 exec 命令；战斗里可以把敌人气血设为 1 快速通过）。每条门槛路线、打输重来、分支都要走到。
8. 更新文档：STORY.md §7 进度表、TODO-CONTENT.md（删掉的占位、新留的伏笔）、POWER.md §5（新授予的武学）、DEVLOG.md（新的 D-xxx 条目，写清取舍）。
9. 本地提交。**只有用户说"commit + push"才推送**（推送会直接部署到公开网站）。
10. 用户暂时不能回复时：自己选合理的方案，做完记进 DEVLOG，说明是代为决定的，等用户回来审阅。
