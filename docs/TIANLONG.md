## 1. 基本约定

| 项目 | 约定 |
|---|---|
| 主线 id | `tianlong`。目录 `content/tianlong/`：`hook.md`（开端，总是加载，保持精简）＋ `ch01.md`、`ch02.md`…… |

## 2. 世界地图：现有的和要新增的

**现有城市**（车马行相通）：临安、嘉兴、襄阳、洛阳（含少林寺）、长安（含华山、终南山）、成都（含唐家堡）。路线：临安—嘉兴 1 日、临安—襄阳 7、襄阳—洛阳 4、襄阳—成都 8、洛阳—长安 4、长安—成都 9。

**天龙八部要用到、现在没有的地方**，建议这样处理：

| 地点 | 建议 |
|---|---|
| 大理 | **新城市**（`city` 块，有车马行、市集、钱庄、客栈、衙门、武馆）。和成都相通（建议 6~7 日）。 |
| 无量山、万劫谷 | 大理附近的剧情地区（`tianlong.*` 房间，从大理某处用 `patch` 加出口） |
| 苏州、燕子坞、曼陀山庄 | 嘉兴附近的剧情地区（从嘉兴用 `patch` 加出口，比如坐船），或者新城市苏州 |
| 聚贤庄 | 洛阳附近的剧情地区 |
| 少林寺 | **已有**（`shaolin.*`，是可以拜师的门派驻地）。剧情只用 `patch` 往少林的房间里加文字、NPC、出口；剧情专属的地方（藏经阁深处等）建 `tianlong.*` 房间 |
| 雁门关、辽国南京 | 北方剧情地区，从洛阳或长安出发 |
| 西夏、天山灵鹫宫 | 剧情地区，从长安出发 |

**新增城市的注意事项**：
- 城市格式照现有的抄（如 `content/world/chengdu.md`）。**不要运行 `tools/gen_cities.py`**：它会覆盖所有已有城市文件，而那些文件已经手改过。
- 跑商规则（ECONOMY.md §3，D-077）：城市的 `goods` **只列 2~3 样本地特产**，倍率 0.6~0.7；外地货的价格由引擎按离产地的路程自动算。可以新增货物（`content/world/goods.md`），但每种货至少要有一个产地。新城市加入后，别处的外地货价格会因为路程变化自动调整，跑一下 `node tools/validate.mjs` 即可。
- 武馆：在 `content/world/wuguan.md` 里照格式给新城市加一个。

## 3. 和已有门派、系统的关系

- **少林**是可拜师的门派。天龙里少林戏份很重（玄慈、虚竹、扫地僧），可以给少林弟子写专属的对话分支（`?sect:shaolin`），但不要改门派本身的机制（阶位、武学、任务）。
- **丐帮**也是可拜师的门派。乔峰是前任帮主，可以给丐帮弟子写专属分支（`?sect:gaibang`）。
- **降龙十八掌属于丐帮**，剧情不能传授（玩家只能拜师学）。乔峰作为 NPC 队友时可以用它（NPC 用 `enemy` 块定义，武功随便配）。
- **天龙特有的武学**（凌波微步、北冥神功、一阳指、六脉神剑、天山折梅手、天山六阳掌、小无相功、斗转星移……）由剧情传授：
  - 定义写在 `content/world/arts.md`（D-083：合击要认得它们），id 用 `tianlong.` 前缀，在文件末尾加一个"天龙八部"小节。
  - 按 POWER.md 的规则安排：**先给低上限，随剧情用 `cap:` 提高**，每次都要满足"威力 ≤ 到这一章为止打赢过的最强战斗力"。`node tools/validate.mjs` 会检查。
  - 六脉神剑、北冥神功这类终极武学，最终上限要放在最后几章，对应的敌人战斗力要配得上。
- **新机制**：如果某门武学需要现在没有的机制（比如北冥神功吸人内力的内功特性、斗转星移的反弹），先在 DEVLOG 写清楚需求，告诉用户，由用户决定是这边实现还是交给主线会话。不要大改引擎（见 §6）。现有的招式效果：内伤、点穴、破绽、缴械、吸内、化内、群攻（D-081）；辅助效果：疗伤、回气、振奋、护体、解穴；轻功特性见飞燕身法（`traits:`）。

## 6. 多会话协作规则（重要）

主线会话（负责引擎、系统、射雕等）和天龙会话会同时改这个仓库。为了不互相踩：

1. **最好在单独的 git worktree / 分支里工作**，写完一个阶段再合并回 `main`。如果和主线会话共用同一个目录：
   - 提交时**只 `git add` 自己的文件**（写明路径），**绝不用 `git add -A`**，否则会把对方写到一半的东西提交进去。
   - 不要 `git checkout`、`git stash`、`git reset` 共用目录里的文件。
2. **天龙会话拥有的文件**：`content/tianlong/**`、`docs/TIANLONG.md`、新建的城市文件（如 `content/world/dali.md`）。
3. **共用文件，只追加、不改别人的部分**：
   - `content/index.json`：只加 `tianlong` 这一项和新城市文件。
   - `content/world/arts.md`、`content/world/combos.md`、`content/world/wuguan.md`、`content/world/goods.md`：在末尾加"天龙八部"小节。
   - `docs/STORY.md` §7 进度表、`docs/POWER.md` §5 授予表、`docs/TODO-CONTENT.md`、`docs/WRITING.md` §10 天龙那张表：只加或改天龙的行。
4. **开发日志编号**：天龙会话的条目从 **D-200** 开始编号（D-200、D-201……），标题后注明"（天龙）"。主线会话继续用 D-086 往后的编号，两边不会撞号。
5. **引擎代码（`src/`、`tools/`）尽量不动**。需要新机制时，先写在 DEVLOG 并告诉用户，由用户安排。确实要改的，改动要小、写清楚，并告诉用户。
6. **只有用户说"commit + push"才推送。**
7. 提交前跑 `node tools/validate.mjs`。如果报错来自对方正在改的文件，告诉用户，不要去"修"对方的文件。
