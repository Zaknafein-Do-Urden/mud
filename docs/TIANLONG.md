## 1. 怎么进去，怎么测

**入口**：成都车马行（`chengdu.station`）里常跑南边的马锅头。`content/tianlong/hook.md` 用 `patch` 给他的对话加了一个选项，入口对话里 `!start:tianlong`，随后 `flag:tianlong.ch1` 把人引到大理。

**要从中间某一章开始看**，最省事的办法是照通关脚本的做法：在 Node 里建 `Game`，把前置标记直接塞进 `state.flags`，再 `g.enter(<章节的 start 房间>)`。脚本里的 `newGame` / `pick` / `ex` / `win` 都是现成的。

```bash
node tools/validate.mjs               # 引用、命名空间、锁定规则、剧情武学战力规则
node tools/power.mjs                  # 武学威力 / 敌人战斗力报表
node tools/balance.mjs <战斗id> [次数] # 胜率模拟（注意 §7 的坑）
node tools/goalcheck.mjs tianlong     # 当前目标的连贯性
node tools/exitcheck.mjs              # 出口有没有被别的主线顶掉
node tools/playtest-tianlong.mjs      # 四条路线走完二十四章（约一秒半）
PLAYTEST_VERBOSE=1 node tools/playtest-tianlong.mjs   # 带计时和即时报错
```

**六脉神剑的六招按等级解锁**：商阳 0、少泽 20、少商 40、中冲 60（群攻）、关冲 80、**少冲 140**。少冲剑的等级特意卡在第二十三章放开的上限上，在那之前练到顶也使不出来（POWER.md §8）。

**北冥神功的吸内力**是这条线唯一加过的引擎机制（D-214）：内功块写 `absorb:`，攻击未被克制时按 `伤害 × absorb` 从对手身上抽内力到自己身上，**故意不夹 maxMp**（可以临时超上限），而内力不入存档，所以战斗结束上限不变。星宿派的"化内"正好是它的反面，第十三、十五、十七、二十一章都拿这一点做文章。

## 5. 标记（flag）

只写 `tianlong.*`，可以读别人的。命名惯例：

| 形状 | 含义 | 例 |
|---|---|---|
| `tianlong.started` | 主线开始 | hook |
| `tianlong.chNN` | 第 NN 章开始（章节检查点就设在这里） | `tianlong.ch17` |
| `tianlong.chNN_done` | 第 NN 章完成（`chapter` 块的 `done:` 读它） | `tianlong.ch17_done` |
| `tianlong.cNN_xxx` | 第 NN 章章内进度 | `tianlong.c22_well`（井口破了） |
| `tianlong.cNN_byXXX` | 玩家选了哪条路（**只记录，不影响后面**，留给以后做差异用） | `tianlong.c22_bypai`／`bymian`／`byying` |
| `tianlong.lead_xxx` | 指向下一章的引子 | `tianlong.lead_nanjing` |
| `tianlong.beat_xxx` | 打赢了本来会输的那一场 | `tianlong.beat_yue`、`tianlong.beat_jmz` |
| `tianlong.tl_done` | **全线通关** | 第二十四章章末 |

**没人读的标记**（留着给以后用）：`beat_yue`、`beat_jmz`、各章的 `..._byXXX`、`tl_done`。要做支线、要让 NPC 认出玩家，这些是现成的钩子。

## 7. 工具与检查流程

照 [WRITING.md §9](WRITING.md) 的清单走。三个和这条线特别相关的坑：

1. **`balance.mjs` 的数字是有口径的**（D-227）。引擎的自适应气血只用 40 次模拟拟合，会过拟合，报出来的胜率能比真实值低十几个百分点；`balance.mjs` 已经改成 120 次。随机种子是固定的，所以**同一场战斗跑多少遍结果都一样**——"多跑几次看看"没有意义，看到 50% 出头又调不动的数字，先怀疑量法，别急着改内容。
2. **`exitcheck.mjs` 要跑**（D-230）。这条线上一次就查出七处被顶掉的出口，最严重的一处让玩家走完第二十章之后出不了兴庆府——而通关脚本发现不了，因为它用 `g.enter()` 直接跳房间，不走路。
3. **`goalcheck.mjs` 要跑**（D-226）。上一章的收尾目标（"本线暂告一段落"之类）忘了删，会一直挡在玩家眼前，`validate` 查不出来——这条线上就藏过一个，挡了十三章。
4. **通关脚本关掉了自适应**（`globalThis.MUD_SKIP_ADAPT`，D-226/D-229）。好处是一轮从七八分钟压到一秒半；代价是敌人不再减伤，所以"打赢"的辅助函数把敌人气血压到 1 的同时也把 `dmgx` 清零。改脚本时别把这一条删了。

## 10. 多会话协作规则

主线会话（引擎、系统、射雕）、笑傲会话和天龙会话同时改这个仓库。

1. 提交时**只 `git add` 自己的文件**（写明路径），**绝不用 `git add -A`**；不要 `git checkout` / `git stash` / `git reset` 共用目录里的文件。
2. **天龙会话拥有的文件**：`content/tianlong/**`、`content/world/dali.md`、`content/world/suzhou.md`、`docs/TIANLONG.md`、`tools/playtest-tianlong.mjs`。
3. **共用文件只追加、不改别人的部分**：`content/index.json`（只动 `tianlong` 那一项）、`content/world/arts.md`、`combos.md`、`wuguan.md`、`goods.md`（末尾的天龙小节）、`docs/STORY.md` §7、`docs/POWER.md` §5、`docs/TODO-CONTENT.md`、`docs/WRITING.md` §10 的天龙那张表。
4. **开发日志编号**：天龙会话用 **D-200 ~ D-299**，标题后注明"（天龙）"。眼下用到 **D-230**。
5. **引擎代码（`src/`）尽量不动**。这条线一共只动过三处，每处都在 DEVLOG 里写了理由：`src/combat.js` 的 `absorb`（D-214）、`src/power.js` 的吸内加成、`src/game-martial.js` 的 `MUD_SKIP_ADAPT` 测试开关（D-226）。再要动引擎，先写进 DEVLOG 并告诉用户。`tools/` 下新加过两个脚本：`goalcheck.mjs`（D-226）、`exitcheck.mjs`（D-230），都是新文件，不碰别人的。
6. **只有用户说"commit + push"才推送**；推送前改 `src/version.js` 的版本号。
7. 提交前跑 `node tools/validate.mjs`。报错如果来自别人正在改的文件，告诉用户，别去"修"对方的文件。
