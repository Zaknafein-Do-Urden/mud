## 5. 多会话协作规则

2. **这条线拥有的文件**：`content/xiaoao/**`、`content/world/fuzhou.md`、`content/world/hengyang.md`、`docs/XIAOAO.md`、`tools/playtest-xiaoao.mjs`、`tools/balance-xiaoao.mjs`。

   - 共用文件被别人同时改过时，**从 HEAD 取一份、只重放自己的改动再暂存**（`git hash-object -w` + `git update-index --cacheinfo`），不要整文件提交。
4. **开发日志编号**：笑傲 D-300 起（现已用到 D-340）。主线会话 D-086 起，天龙 D-200 起。
5. **引擎代码（`src/`、别人的 `tools/` 脚本）不动**。需要新机制先写进 DEVLOG 并告诉用户。
6. **只有用户说"commit + push"才推送**；推送前改 `src/version.js` 的版本号（新章节加第二位）。
7. 提交前跑 `node tools/validate.mjs`；报错来自别人正在改的文件时告诉用户，不要去"修"对方的文件。

## 6. 踩过的坑（后面写剧情的人省点事）

1. **同一个房间里的连续剧情，一律用选项接**（`-> 下一段`）；房间触发只用来接"换了地方"的那一段。同一次进房间，引擎会把所有条件满足的触发都跑一遍，后一个会把前一个的选项顶掉（D-312，全线踩了五次）。
2. **正文写了"你已经到了别处"，就必须用没有选项的过场 + `goto:` 把人带过去**（D-211、D-323）。第一章"跟他去荔香楼"原先漏了这一步，玩家点完屏幕上什么也不动，看着像卡死。
3. **选项只指方向时，正文末尾要写一行"（主线：……）"**。
4. **`?party:2` 这类条件是在"对话打开的那一瞬"过滤的**：测试要在进入那段对话之前就把队伍准备好；**进战斗之前要把假队伍散掉**，否则引擎给队员建单位时会崩（D-335）。
5. **往共享房间挂出口前先查方向**（D-327）。
6. **测试脚本用 Edit 改，不要用 `node -e` 拼字符串**：shell 吃掉引号之后 `String.replace` 找不到锚点也不报错，会静默跳过——第九、十章的"通过"曾经是假的（D-329）。脚本里的替换函数现在找不到锚点就 `exit 1`。
7. **`pick` 的关键词不要带标点**：正文里是全角引号，对不上（D-333）。

## 7. 验收这条线的四条命令

```bash
node tools/validate.mjs            # 引用、命名空间、锁定规则、剧情武学的战力规则
node tools/power.mjs               # 武学威力与敌人战斗力；笑傲的 36 次授予与提限都要是 ✓
node tools/playtest-xiaoao.mjs     # 五条路线把十八章从头走到尾
node tools/balance-xiaoao.mjs 200  # 全线必胜战的胜率表（按本线进度分五档角色）
```

**不要用 `tools/balance.mjs` 测这条线**：那边的四档角色练的是基础武功和丐帮武功，和笑傲的玩家对不上，读数会荒腔走板（同一场战斗开局 100%、入门 0%）。原因和替代办法见 D-340。

**关于难度还要知道两件事（D-340）**：

1. 自适应生效时，**改敌人的等级和血量对胜率几乎没有影响**——它把敌人气血缩放到"约 6 回合打完"，你乘多少它就除多少。实测把林平之从战斗力 335 降到 299、终章岳不群从 441 降到 394，胜率纹丝不动（55%、57%），所以这两处又改了回去。
2. 真正还有效的，是**把敌人从"撞下限"的区间拉回来**（气血系数 0.25~3、伤害 0.1~8）。撞了下限，战斗就退化成"打得完／打不完"；第九~十八章的敌人已经统一降过血（`hpx` 0.45~0.6）把它们拉了回来。
