## 3. 和已有门派、系统的关系（重要）

- **华山派已经是可拜师的门派**（`content/world/huashan.md`，侧重巧，镇派绝学独孤九剑，师父穆清风）。笑傲线里的华山派掌门是岳不群。
  - 处理（D-302）：**穆清风是华山的授艺长老，岳不群是掌门**。剧情只用 `patch` 往华山的房间加文字、NPC、出口，剧情专属的地方（思过崖后洞等）建 `xiaoao.*` 房间。**不要改门派本身的机制**（阶位、武学、任务、考核）。
  - **独孤九剑属于华山派，剧情不传授**（POWER.md §4：门派武学走阶位）。风清扬那一章可以让玩家"见识"它、拿到相关的奖励（悟性、潜能、一门别的武学），但要学独孤九剑只能拜师。令狐冲作为 NPC 队友时可以用它。
- **少林、武当**也是可拜师的门派，方证、冲虚可以作为剧情 NPC 出场，但不改门派机制。
- **笑傲特有的武学**由剧情传授，定义写在 `content/world/arts.md` 末尾的"笑傲江湖"小节（D-083：合击要认得它们），id 用 `xiaoao.` 前缀：
  - 已有：翻天掌（玩家，上限 25）、辟邪剑法（林平之专用）、松风剑法／摧心掌（青城派敌人，写在章节文件里）。
  - 计划见 POWER.md §9。**辟邪剑谱、葵花宝典、吸星大法这三门可以传给玩家**（D-309，用户定）：一开始压很低的上限，随剧情一档档放开，**全线打通之后才给完整版**（办法同天龙的六脉神剑 D-215）。每一档都要过 POWER 规则 1，终章的敌人要配得上 240 以上的战斗力。
- **新机制**：需要现在没有的机制时（比如吸星大法吸人内力——引擎已有内功 `absorb`，可以直接用；再比如独孤九剑"料敌先机"式的预兆揭示），先在 DEVLOG 写清楚需求并告诉用户，不要大改引擎。
  现有的招式效果：内伤、点穴、破绽、缴械、吸内、化内、群攻；辅助效果：疗伤、回气、振奋、护体、解穴；轻功特性见飞燕身法（`traits:`）。

## 6. 多会话协作规则

和 TIANLONG.md §6 相同，只把"天龙"换成"笑傲"：

1. 提交时**只 `git add` 自己的文件**（写明路径），**绝不用 `git add -A`**；不要 `git checkout`／`stash`／`reset` 共用目录里的文件。
2. **笑傲会话拥有的文件**：`content/xiaoao/**`、`docs/XIAOAO.md`、`tools/playtest-xiaoao.mjs`、新建的城市文件（如 `content/world/fuzhou.md`）。
3. **共用文件只追加自己的小节**：`content/index.json`（只加 `xiaoao` 一项和新城市文件）、`world/arts.md`、`world/combos.md`、`world/wuguan.md`、`world/goods.md`（末尾"笑傲江湖"小节）、`docs/STORY.md` §7、`docs/POWER.md` §9、`docs/TODO-CONTENT.md`、`docs/WRITING.md` §10 笑傲那张表。
   - 例外：新城市要和旧城市互通送信差事时，需要往对方城市文件里加两个选项（福州 ↔ 临安就往 `world/linan.md` 加了，D-303）。只加，不改别人已有的行。
4. **开发日志编号**：笑傲从 **D-300** 起。主线会话 D-086 起，天龙 D-200 起。
5. **引擎代码（`src/`、`tools/` 里别人的脚本）尽量不动**；自己的测试脚本单独建一个文件。
6. **只有用户说"commit + push"才推送。**
7. 提交前跑 `node tools/validate.mjs`；报错来自别人正在改的文件时告诉用户，不要去"修"对方的文件。
