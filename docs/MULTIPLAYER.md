# 联机设计（草案 v0.2）

> 状态：**第一版已实现**（2026-10-16）。实现细节见 §9。
> 已确认的原则来自 2026-10-16 的讨论，见 [DEVLOG.md](DEVLOG.md) D-009 ~ D-011。

## 1. 一句话概括

**房主带着朋友走自己的主线。** 房主推进剧情；客人是"助拳的朋友"，只出战力、拿战斗收益，不影响自己的主线。

## 2. 角色与权限

| | 房主 | 客人 |
|---|---|---|
| 运行游戏规则 | ✅（房主浏览器就是这局的服务器） | ❌ |
| 移动 | ✅ 决定去哪 | 自动跟随，不能自己走 |
| 与 NPC 对话、做剧情选择 | ✅ | ❌，但能看到全部对话文字 |
| 查看（look、状态、背包） | ✅ | ✅ |
| 建议 | — | ✅ `建议 北`、`建议 2`、`建议 对话 说书先生` |
| 战斗 | ✅ 自己出招 | ✅ 自己出招（战斗中人人平等） |
| 聊天 | ✅ | ✅ |
| 剧情标记、剧情物品 | 写入自己的存档 | **不获得** |
| 战斗收益（潜能、银两、普通掉落） | ✅ | ✅ 写入自己的存档 |

## 3. 流程

```
客人在自己游戏中走到任意旅店                   房主在自己游戏中走到任意旅店
        │                                              │
        │                                      「联机 → 开设队伍」
        │                                      得到暗号：燕子坞-7342
        │                ◄──── 暗号通过微信等告诉朋友 ────
「联机 → 加入队伍 燕子坞-7342」
        │
        ├─ 版本检查（内容版本必须一致）
        ├─ 发送角色卡（见 §5）
        ▼
  客人的画面切换为"房主的世界"，出现在房主身边
        │
        │   …… 房主推进剧情，客人跟随、建议、并肩战斗 ……
        │   每场战斗结束 → 房主发送"结算包" → 客人立即写入本地存档
        │
   队伍解散 / 被踢出 / 房主掉线 / 客人自己退出
        ▼
  客人回到自己的世界，位置就是加入时所在的旅店
  房主留在原地继续
```

### 3.1 为什么必须在旅店

- **客人**：加入时客人的位置一定是旅店，解散后"回到旅店"就是回到原位，客人自己的世界状态没有被动过，不需要任何合并。
- **房主**：在旅店开队伍，是一个自然的"招呼朋友"的地方，也方便剧情上解释。
- ✅ 房主开队后可以带队去任何地方。解散时房主留在原地，客人回到自己世界中加入时的旅店（D-017）。

### 3.2 剧情选择

- 只有房主能选。客人可以 `建议 2`，房主那边显示"阿青建议：2. 你怎么知道？"。
- 房主可以输入 `采纳` 一键执行最近一条建议。
- 不做投票（决定权在房主，按讨论结论）。

## 4. 收益规则

| 收益 | 房主 | 客人 |
|---|---|---|
| 战斗潜能（用于修炼武功，见 COMBAT.md §7） | 全额 | **全额**（不平分，鼓励组队） |
| 银两 | 各自掷骰 | 各自掷骰 |
| 普通掉落（丹药、材料、普通装备） | 各自掷骰（个人掉落，不抢） | 各自掷骰 |
| 剧情掉落（标 `quest` 的，如秘籍、信物） | ✅ | ❌ |
| 剧情对话给的东西（`give:` 效果） | ✅ | ❌ |
| 剧情标记（`flag:` 效果） | ✅ | ❌ |
| 战斗中学会的东西（如偷学到敌人招式） | ✅ | ✅ |

✅ **偷学、顿悟类收益客人也能得**（D-017）。这是"陪朋友打架"最有吸引力的回报。每种只能领悟一次，不触发任何剧情。

### 4.1 结算

- **每场战斗结束立即结算**，不等散场。掉线最多损失一场战斗。
- 结算包带序号：`{session, seq, potential, money, items}`。客人存档记录已收到的最大序号，重复收到的包直接忽略（防止网络重发导致重复入账）。
- 客人的气血、内力在队伍中由房主管理；回到旅店时按"在旅店休息"处理，回满。

## 5. 角色卡

客人加入时发给房主，房主用它在自己的世界里生成客人的战斗单位：

```json
{
  "name": "阿青",
  "attrs": { "根骨": 18, "身法": 22, "悟性": 15 },
  "inner": { "id": "beiming", "lv": 45 },
  "skills": [ { "id": "liumai_jian", "lv": 60 }, { "id": "lingbo", "lv": 50 } ],
  "loadout": ["liumai_jian", "tianshan_zhang", "lingbo", "taiji_quan"],
  "items": { "jinchuang_yao": 3 }
}
```

- 只发战斗相关数据，不发剧情标记（房主不需要，也避免剧透）。
- 角色卡无法验证真伪（见 D-005），朋友间合作，接受。
- 战斗中客人消耗的丹药，在结算包里扣除。

## 6. 等级差

- 高手带新手是**允许**的，而且是好事（老玩家带朋友入坑）。
- 敌人强度只按**人数**调整，不按客人等级调整，否则高手来帮忙反而让战斗变难。
- ❓ 要不要防止"高手一个人秒光，新人房主什么都没体验到"？我的倾向是不防，玩家自己会调节。

## 7. 掉线与异常

| 情况 | 处理 |
|---|---|
| 客人掉线 | 从队伍移除；房主那边提示"阿青离开了队伍"；正在战斗中则其单位视为倒地 |
| 客人重连 | 在旅店重新输入暗号加入即可 |
| 房主掉线 | 队伍解散，所有客人回到自己的旅店；已结算的收益都在 |
| 全队战败 | 所有人"被人救起"，队伍整体回到**房主**最近的旅店，队伍不解散 |
| 版本不一致 | 拒绝加入，提示双方刷新页面 |

## 8. 网络协议

传输与信令方案见 D-007（WebRTC + Trystero）。消息类型：

| 方向 | 消息 | 内容 |
|---|---|---|
| 客→主 | `hello` | 游戏版本、内容版本哈希 |
| 客→主 | `join` | 角色卡 |
| 主→客 | `welcome` / `reject` | 队伍成员列表 / 拒绝原因 |
| 客→主 | `cmd` | 一条命令文本（look、建议、聊天…） |
| 主→客 | `out` | 要显示的文字条目（房主按接收者生成，每人可以不同） |
| 主→客 | `combat` | 战斗回合开始：敌我状态、可选招式、倒计时 |
| 客→主 | `act` | 本回合出招 |
| 主→客 | `settle` | 结算包 |
| 双向 | `ping` | 心跳，10 秒无响应视为掉线 |
| 主→客 | `bye` | 解散 / 踢出 |

- 规模：最多 4 人（房主 + 3 客人）。
- 房主权威：客人永远不自己算结果，只显示房主发来的文字。所以客人端几乎不需要游戏逻辑，联机时客人只是一个"终端"。

## 9. 实现（第一版）

### 9.1 怎么玩

1. 房主在**旅店或门派驻地**点"开设队伍"。
2. 客人也在旅店或门派驻地点"**搜索队伍**"，列表里是**和客人在同一个旅店或门派驻地、队伍未满**的房主和队伍人数（每 3 秒刷新，版本不同的会标出来），点"加入"即可（D-055、D-056）。房主离开那里或者满员后，别人就搜不到了。
   - 房主可以在队伍栏点成员名字后面的"踢出"，或输入 `踢出 名字`，把人请出队伍。被请出的人回到自己加入时所在的旅店。
3. 客人跟随房主行动：
   - 点击出口、人物、对话选项会自动变成**建议**。房主那边显示"阿青建议：北 [采纳]"，点一下就执行。
   - "说话"按钮或 `说 内容` 发队伍聊天。
   - 人物面板（状态、武功、天赋、背包）在客人本地照常使用；调整装备、天赋后会自动同步给房主。
   - 客人在队伍中不能修炼。
4. 战斗：所有人同时出招，**每回合限时 20 秒**，超时自动调息。队友已选的招式实时显示在战斗面板上。只有房主能下令撤退。
5. 每场战斗结束，客人立即得到实战经验（胜负都给）和潜能（胜利时），写进客人自己的存档。
6. 客人点"离开队伍"，回到自己加入时所在的旅店；房主点"解散队伍"，所有客人各自回去。

**同一台电脑测试**：地址栏加 `?net=local` 使用浏览器内部通道（不走网络），再加 `?slot=2` 用另一个存档。例如开两个标签页：`/?net=local` 和 `/?net=local&slot=2`。

### 9.2 代码结构

| 文件 | 作用 |
|---|---|
| `src/net/transport.js` | 传输层：Trystero（WebRTC + Nostr 信令）和 local（BroadcastChannel）两种实现，接口相同 |
| `src/game-party.js` | 引擎的联机部分（房主一侧）：成员、客人命令、组队出招、超时、战后结算 |
| `src/ui/party.js` | 联机控制：开设 / 加入、消息收发、按接收者分发输出、倒计时、客人一侧的结算 |
| `src/combat.js` | 战斗支持多个玩家单位（`pid` 区分），敌人按我方战斗力浮动，客人按半个人算（D-115） |

### 9.3 输出分发

- 引擎的输出条目可以带 `to` 字段：没有 `to` 的发给所有人，有 `to` 的只给那个人。看破虚招的提示、客人的私人提示、房主收到的建议都用 `to`。
- 房主自己的"私事"命令（看状态、买卖、存钱、修炼……）不广播。
- **组队战斗用真名**（"林雪使出一招……"），每个接收者看到的文字再把自己的名字换成"你"。所以人人看到的都是自己视角的战斗描述（D-048）。

### 9.4 实际协议

| 方向 | 消息 | 内容 |
|---|---|---|
| 客→主 | `hello` | 协议版本、内容指纹、角色快照 |
| 主→客 | `welcome` / `reject` | 暗号、房主名 / 拒绝原因（版本不一致、满员） |
| 客→主 | `cmd` | 命令文本（战斗出招、看、说、建议） |
| 客→主 | `char` | 更新后的角色快照（调整装备、天赋、结算之后） |
| 主→客 | `out` | 发给这位客人的输出条目（已换成他的视角） |
| 主→客 | `combat` | 他的战斗面板数据、本回合剩余秒数；不在战斗中时为 null |
| 主→客 | `pos` | 房主所在房间、该区域房主去过的房间（客人地图显示用） |
| 主→客 | `members` | 队伍名单 |
| 大厅 | `search` | 客人每 3 秒发一次，带上自己所在的房间 |
| 大厅 | `party` | 房主只回应同一房间、且队伍未满时的搜索：队伍房间号、房主名、人数、上限、协议版本、内容指纹 |
| 大厅 | `gone` | 房主解散时通知 |
| 主→客 | `settle` | 战后结算：序号、各武功经验、潜能、气血 |
| 双向 | `bye` | 离队 / 解散 |

心跳和掉线检测由传输层负责（Trystero 自带；local 通道每 2 秒心跳，8 秒没有消息视为离开）。

### 9.5 已知限制

- 房主刷新页面，队伍就解散了（队伍状态不存档）。
- 没有 TURN 中继服务器，少数网络环境（对称 NAT、公司网络）连不上（D-007）。
- 公共 Nostr 中继偶尔有个别连不上，Trystero 会同时连多个，测试中不影响。
- 战斗中途加入的客人要等下一场战斗才参战。
- 劫道战败：只有房主（货主）损失货物和现钱，客人不受损失。
- 劫道时客人全额参战，劫匪只按房主一个人放缩，不因客人变强（D-122）；马车奇遇组队时照样触发，客人各得一份钱和潜能（D-126）。
