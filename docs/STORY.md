# 剧情结构设计（草案 v0.1）

> 状态：**讨论中**。剧情来源已定：金庸作品同人（§6，D-025）。时代方案默认采用 A（§3），待最终确认。
> 相关决策：[DEVLOG.md](DEVLOG.md) D-024、D-025。
> **写剧情之前先读 [WRITING.md](WRITING.md)**：用户对剧情的全部要求汇总，以及各主线的章节规划。

## 1. 目标

- **一部小说 = 一条主线**。
- 若干条主线在同一个江湖里**并行推进**：玩家可以在临安听到 A 线的传闻，转身去襄阳推进 B 线，再回来继续 A 线。
- 主线之间可以有交集（同一个地点、同一本秘籍、客串人物），但不能互相卡死。

## 2. 玩家的身份

玩家是一个**原创角色**，不扮演原著主角。

| 方案 | 说明 | 问题 |
|---|---|---|
| 扮演原著主角 | 例如在射雕线里当郭靖 | 并行多线时身份冲突（上午郭靖下午张无忌）；剧情只能照搬原著，没有选择空间 |
| **原创角色亲历其事** | 玩家是一个江湖新人，卷入各部小说的事件，与原著人物同行、相助、对立 | 需要给玩家安排合理的位置，但选择空间大，可以改变部分走向 |

建议后者。这也是《金庸群侠传》的做法。

## 3. 时代问题

各部小说的时代不同，比如北宋、南宋、元末、明代，放进同一个江湖就会穿越。

| 方案 | 说明 | 代价 |
|---|---|---|
| A. 一个江湖，不讲时间线 | 所有人物同时存在，同一张地图 | 有违和感，但玩家普遍接受（《金庸群侠传》《武林群侠传》） |
| B. 分时代、多张地图 | 每条主线一个时代地图，用"说书人讲故事 / 入梦 / 读残卷"进入 | 地图不能复用，工作量大；主线之间难以交集 |
| C. 一个江湖，主线按时代分层 | 地图共用，但同一时间只有一条主线"当前激活"，切换时用叙事过渡（"十年后……"） | 结构最复杂 |

我倾向 **A**。理由：地图共享，写一个临安城所有主线都能用；交集最自然；实现最简单。

## 4. 数据结构

### 4.1 主线定义

```
=== storyline: shediao
name: 射雕英雄传
hook: linan.teahouse          # 开端在哪里触发（比如茶楼听书）
xiuwei: 10-150                # 建议修为（所有武功等级之和），江湖面板显示"建议修为 10~150"（D-075）
---
一句话简介，显示在"江湖传闻"里。

=== chapter: shediao.1
storyline: shediao
# 章节名原创，不用原著回目
name: 牛家村夜雪
---
章节标题页的文字。
```

### 4.2 命名空间

- 每条主线的 id 和剧情标记都带前缀：`shediao.*`、`tianlong.*`。
- 共享世界的标记用 `world.*`，例如"临安城门已修好"。
- **规则：一条主线只能写自己命名空间的标记**，但可以**读**其他主线和 world 的标记。校验脚本会检查这一点。

### 4.3 目录

```
content/
  index.json
  world/            共享地图：城镇、野外、旅店、通用 NPC
    linan.md
    xiangyang.md
  shediao/          射雕线：剧情、专属地点、人物、武学
    ch01.md
    ch02.md
  tianlong/
    ...
```

- 主线内容**按需加载**：玩家触发了某条主线的开端，才加载它的文件。首屏只加载 world 和已开始的主线。
- 这样即使最终有十几部小说的文本量，首次打开也很快。

## 5. 主线之间的交集与冲突

### 5.1 共享地点的写法

主线只能在共享房间里**追加**条件文字，不能改写别人的内容：

```
=== room: linan.teahouse         # world/linan.md 中定义
...

=== patch: linan.teahouse        # shediao/ch01.md 中追加
---
?flag:shediao.started ?!flag:shediao.ch3_done 说书先生今天讲的是"牛家村风雪夜"。
```

`patch` 块把文字挂到目标房间的描述末尾，NPC 和出口也可以这样追加。

### 5.2 人物归属

- 每个原著人物**归属一条主线**，由该主线负责他的生死去留。
- 别的主线要让他客串时，只能读他的状态，比如他死了就不出场，不能改变他。

### 5.3 共享物品（如同一本秘籍出现在两部书里）

- 物品归 world 所有，各主线通过 `has:` 判断。例如：已经从 A 线得到这本经书的玩家，在 B 线相应剧情里会触发特殊分支。
- 这是"并行推进"最有趣的回报：**一条线的收获在另一条线里被认出来**。

### 5.4 武学平衡

- 从一条线学到的武功在所有线通用。
- 每条主线标注建议水平（`level`）。玩家可以自己选择先走哪条，"江湖传闻"面板会提示难度。
- 敌人强度按主线的章节固定，不随玩家等级浮动。先练强再去低级线，就是爽快的碾压。

## 6. 剧情来源：金庸作品同人（已定，D-025）

**金庸作品目前仍在版权保护期内。** 中国著作权保护期为作者终生加死后 50 年；金庸先生于 2018 年去世，保护期到 2068 年底。

需要注意的几点：

- GitHub Pages 是**公开网站**，任何人都能访问。即使不收费，也属于向公众传播。
- 风险不只是照抄原文。金庸诉江南《此间的少年》一案中，江南借用了金庸小说的人物名称和关系，法院判定构成不正当竞争并判赔，而那还是一部原创故事的小说。
- 游戏改编权是很值钱的授权，已有多款正式授权的金庸游戏，权利方维权积极。

可选的方向：

| 方案 | 说明 | 风险 |
|---|---|---|
| **A. 原创故事，金庸式风格** | 原创人物、门派、武功，但借鉴金庸的气质和常见桥段（灭门、秘籍、正邪、侠之大者） | 无 |
| **B. 公有领域武侠作品** | 作者去世超过 50 年、已进入公有领域的作品：唐传奇（聂隐娘、虬髯客、红线盗盒）、《水浒传》《三侠五义》《七侠五义》，以及民国旧派武侠：还珠楼主《蜀山剑侠传》、平江不肖生《江湖奇侠传》、白羽《十二金钱镖》、郑证因《鹰爪王》、朱贞木《七杀碑》 | 无（发布前需逐部核实作者卒年） |
| C. A + B 混合 | 用公有领域作品做几条主线，再穿插原创主线 | 无 |
| D. 金庸同人 | 照你最初的想法 | 公开部署有侵权风险，最坏情况是收到通知后被迫下架、重写全部剧情 |

我的建议：**C**。"一部书一条主线、多线并行"的结构完全保留：水浒、三侠五义、蜀山、江湖奇侠传各成一线，题材也很丰富，从市井侠义到剑仙奇幻都有。金庸的影响体现在原创主线的风格上。

**决定：D，金庸同人。** 用户已了解风险并决定采用。

### 6.1 写作规则（降低风险，所有贡献者遵守）

1. **不复制原著文字**：所有叙述、对白都原创撰写。不摘抄原文段落、诗词、回目、标志性台词。
2. 情节可以取材于原著的事件，但用游戏自己的视角和文字重新讲述，并且以玩家亲历为主线，而不是复述原著。
3. 武功、人物、门派名称沿用原著（这是同人的意义所在）；招式描述文字原创。
4. 不用原著或任何正版游戏的美术、配乐、封面。

### 6.2 发布与应对

- README 和游戏内"关于"页面声明：非官方同人作品、非商业、版权归原作者及权利人、收到权利人通知即下架。
- **不做任何商业化**：不收费、不放广告、不接受打赏。商业化会显著增加风险。
- **可快速撤下**：每条主线独立在 `content/<主线>/` 目录，world 和原创内容独立。收到通知时，从 `index.json` 移除相应主线即可下线，世界地图和系统不受影响。
- 玩家存档里残留已下线主线的标记时，游戏忽略未知标记，不会出错。

## 7.1 剧情传授的武学

剧情里传授武功秘籍，要按 docs/POWER.md 的规则安排：玩家打得过战斗力 X 的敌人，才能得到威力不超过 X 的武学。秘籍先给低上限，随剧情用 `cap:` 提高。校验脚本会检查。

## 8. 主线战斗规则（D-042）

- 除第一章外，**每个主线章节都要有战斗**。
- **默认必须打赢才能推进**：打输时回到章节开始的状态（本主线的剧情标记回滚到章节检查点，人回到章节的 `start` 房间）。
  - 过程中获得的经验、潜能、金钱、物品都保留。
  - 主线对话里的**一次性奖励**（`give`、`money`、`potential`、`learn`、`rep`）只发一次，重来时不会重复获得。
- **必败剧情战**：战斗块写了 `lose:` 分支，就是允许打输的剧情战。输了剧情照常继续；万一打赢，有特别奖励。例如第二章的段天德：打赢可以夺下他的佩刀，另得 150 潜能。
- 写作要点：
  - `chapter:` 效果一般写在同一组效果的**最前面**，检查点里才不含本章开头设下的标记，重来时会重新触发开头。
  - 例外：如果 `start:` 房间离开头剧情很远（如第四章开头在车马行、重来在码头），就把本章的起始标记写在 `chapter:` **前面**（`do: flag:shediao.ch4 chapter:shediao.4`），重来时保留它，不必回去再看一遍开头。
  - 章节块写 `start:`（重来时回到哪里，应选一个不会立刻再触发本章剧情的地方，方便玩家先去练功）和 `retry:`（重来时的提示文字）。
  - **任务物品和关键标记不能"中途离开就丢"**（D-067）。没有 `lock: true` 的对话，玩家输入别的命令就离开了。所以：
    - 战斗结果、`once` 触发之后的剧情对话，以及触发条件已被关掉之后的对话，一律 `lock: true`。
    - 任务物品尽量在进入对话时就给（`do: give:…`），选项只做确认。
    - 设"已经发生过"的标记，和给物品放在同一个选项里，不要先设标记、下一个对话再给物品。
    - 校验脚本会检查以上几条。
